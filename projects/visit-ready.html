The problem

Clinical trial listings contain dense research terminology and complicated eligibility criteria. Finding a study does not always tell a patient what to ask, what information to gather, or how to prepare for a conversation with the research team.

Visit Ready is a multilingual discovery and preparation platform designed to make that information easier to navigate. We built it in the Healthcare & Biotech track at Hackachusetts 2026.

My contribution

I co-developed Visit Ready with Owen Gachuhi and led the frontend development and user experience design using Kiro IDE, React, and TypeScript.

  • Created the Open Door interface and interactive research Topic Garden.
  • Built a guided search experience and study-detail pages.
  • Created patient preparation tools and worked on the Verification Map experience.
  • Integrated the frontend with our team’s ClinicalTrials.gov data pipeline, tested functionality, and resolved integration issues.
  • Deployed the working application through GitHub Pages.

From discovery to preparation

  1. Explore: browse the Topic Garden or search for a condition or study.
  2. Understand: review study details and plain-language explanations through an English/Spanish interface.
  3. Organize: identify which requirements need personal answers, existing records, or a conversation with the study team.
  4. Prepare: create a preparation card and focused questions for the next conversation.

The Verification Map

A key product decision was to organize eligibility requirements into actionable categories instead of trying to predict whether a patient qualifies.

  • You can answer
  • Check existing records
  • Ask the study team
  • Cannot assess from public information

The original registry requirements remain available. The map supports preparation; it does not produce an eligibility verdict or a match score.

Integration & delivery

The frontend connects to the team’s browser-based ClinicalTrials.gov API v2 pipeline. I worked on functionality testing and integration fixes, then deployed the application as a GitHub Pages site.

Tools: Kiro IDE, React, TypeScript, ClinicalTrials.gov API v2, GitHub, and GitHub Pages.

This is a hackathon prototype. Patient outcomes and usability improvements have not been measured, and the application is not a clinically validated eligibility or medical-advice tool.

What this shows

This project connects my analytical background with hands-on product development: turning complex information into a clearer user journey, building an interactive frontend, and working through the integration needed to ship it.

The Verification Map illustrates the judgment behind that work: make the next step actionable while being explicit about what the product cannot determine.
